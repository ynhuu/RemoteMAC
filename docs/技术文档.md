## 架构

~~~mermaid
flowchart LR
    VD[macOS 虚拟显示器] --> SC[ScreenCaptureKit]
    SC --> VT[VideoToolbox H.264]
    VT --> FQ[原生帧队列]
    FQ --> RP[有界 RTP 发送队列]
    RP -->|WebRTC / DTLS-SRTP| BR[浏览器原生解码与渲染]
    BR -->|键盘 鼠标 触控 DataChannel| IN[macOS 输入注入]
    IN --> VD
    UI[React 控制端] <-->|HTTP 与 WebSocket 信令| API[Go / Gin 服务]
~~~

媒体使用 WebRTC RTP。ICE 协商媒体路径；局域网通常使用 UDP。HTTP 和 WebSocket 负责登录、SDP/ICE 信令、画质配置与虚拟屏调整。

## 模块划分

| 模块 | 主要职责 | 代码位置 |
| --- | --- | --- |
| React 控制端 | 登录、画面、参数、软键盘与本地 WebRTC 统计 | web/src |
| HTTP 与信令 | 登录、健康检查、能力接口、WebSocket 信令 | internal/server |

| 启动入口 | 参数解析、配置载入、正常退出与原生主循环 | cmd/remotemac |

## 启动、认证与会话

- 命令行参数 `-host` 设置 HTTP 监听地址；源码默认值为 `0.0.0.0:8081`，`-version` 打印程序版本并退出。
- Release 构建通过 `VERSION=vX.Y.Z` 注入版本；认证后的 `/api/capabilities` 返回 `version`，控制面板也会显示该版本。
- 服务启动必须提供 REMOTEMAC_TOKEN。源码不会生成、打印或自动保存访问口令。
- 登录成功后使用保存访问口令 SHA-256 十六进制摘要的 HttpOnly Cookie；WebSocket 校验登录状态和同源 Origin。/healthz 不要求登录。
- 当前仅允许一个远程桌面控制会话。新客户端发起 offer 时，服务会关闭旧会话并等待原生虚拟屏清理后再接管。
- 正常关闭会清理采集、PeerConnection、输入状态和虚拟显示器。
- 安装器从 GitHub Release 下载当前架构二进制，以当前图形登录用户创建 LaunchAgent。程序位于 `/usr/local/bin/remotemac`，口令文件为 `~/.config/remotemac/password`，设置位于 `~/.config/remotemac/settings`，启动脚本位于 `~/.local/share/remotemac/run`；日志位于 `~/Library/Logs/RemoteMAC`。

HTTP 登录和信令没有 TLS。Cookie 当前按 HTTP 使用，不能把该服务直接暴露到公网。WebRTC 媒体由 DTLS-SRTP 保护；这不加密登录页、HTTP API 或信令内容。

## 虚拟显示与分辨率

首次连接时，浏览器以远程视频区域的 CSS 尺寸乘设备像素比计算请求尺寸。设备像素比最多取 2，画面选项再按 50%、67%、83% 或 100% 缩放。宽高按 4 像素对齐。

服务端接受的尺寸范围为最小 320×200、总面积最多 25,000,000 像素。尺寸由视口和用户选项决定，网络反馈不会自动降低分辨率。

虚拟显示按以下顺序尝试并通过活动 CoreGraphics 显示模式读取结果：

1. 半尺寸逻辑模式，HiDPI 2×。
2. 原尺寸逻辑模式，HiDPI 2×。
3. 原尺寸 1×。

移动端不强制锁定方向。视口方向变化后，浏览器重新计算尺寸并请求服务端更新；更新失败时尝试恢复此前显示模式和采集配置。

虚拟显示使用 CGVirtualDisplay 与 SkyLight 等系统接口，其中部分是非公开接口。macOS 更新可能改变模式枚举、镜像或权限行为。

## 采集与 H.264 编码

ScreenCaptureKit 将桌面帧交给 VideoToolbox。原生回调送出真实编码视频帧，Go 会话帧队列容量为 2。

VideoToolbox 以硬件 H.264 实时模式编码，不重排帧。服务端会读取 SDP 中的 profile-level-id、max-fs 和 max-mbps，校验初始尺寸、重配尺寸、帧率及关键帧 SPS；浏览器也会根据本机能力协商解码参数。

画质选项如下：

| 设置 | 浏览器选项 | 服务端规则 |
| --- | --- | --- |
| 码率 | 2、5、10、25 Mbps，默认 5 Mbps | 接收后固定应用；服务端和原生编码层范围为 2–50 Mbps |
| 帧率 | 15、30、60 FPS，默认 30 FPS | 固定为所选目标；静止桌面可能输出较低 FPS |
| 画面 | 50%、67%、83%、100% | 按实际视频区域和设备像素比计算虚拟屏尺寸 |
| 鼠标 | 鼠标模式、直接触屏 | 选择相对指针移动或直接触点映射 |

## 媒体传输与恢复

服务会按完整视频帧顺序发送媒体数据，并限制待发送数据量。网络拥塞、帧过期或发送失败时，会丢弃过期待发数据并等待新的关键帧，避免延迟持续增长。

码率和帧率按用户选择应用。网络承载不足时，较高的码率可能导致延迟或卡顿；浏览器显示的实际接收速率也会受画面内容、编码器、网络和解码端影响。

## 输入和浏览器统计

键盘、点击、滚动、触控、文本与按键释放状态通过 DataChannel 传回 Mac。虚拟屏重配期间会拒绝过期坐标；连接关闭时释放全部按键与鼠标按钮。

浏览器本地每秒读取 RTCPeerConnection.getStats()，显示接收码率、解码帧率和 RTT 等指标。统计不会周期性上传给服务端，也不参与码率控制。RTT 和抖动缓冲等指标不是单向屏幕端到端延迟；需要在目标设备上观察真实操作和画面才能评估主观延迟。

## 构建与运行

安装依赖并构建当前架构：

~~~sh
make deps
make build-arm64   # Apple Silicon
make build-amd64   # Intel Mac
~~~

构建时通过 `VERSION=vX.Y.Z` 注入版本号；二进制可使用 `-version` 查询，认证后的 `/api/capabilities` 也会返回 `version`。

手动启动时必须提供口令：

~~~sh
export REMOTEMAC_TOKEN='本机访问口令'
./bin/remotemac-darwin-arm64 -host 0.0.0.0:8081
~~~

安装器从 GitHub Release 下载当前架构二进制；安装器命令、Release 资产、文件位置和卸载方式见[安装与卸载脚本](安装脚本.md)。安装默认监听 0.0.0.0:28080，源码手动启动默认监听端口仍为 8081。

make check 会运行前端生产构建、安装脚本 Shell 语法检查、Go 测试和 go vet。它不覆盖实际 iPhone、iPad、Android WebView、显示权限或不同网络环境验收。make release 会生成 macOS 双架构 ZIP 和 SHA256SUMS，并将 `VERSION` 注入二进制。

## 边界

- 仅支持 macOS 原生桌面采集；Intel 与 Apple Silicon 需要分别构建。
- 首次使用需要屏幕录制权限；键鼠注入需要设备控制（辅助功能）权限。
- 不包含音频、剪贴板、文件传输或 TURN 中继。
- HTTP 认证与信令未加密，只用于可信局域网或已受信任的 VPN。
