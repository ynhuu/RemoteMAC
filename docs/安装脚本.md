# RemoteMAC 安装与卸载脚本

`install.sh` 是面向 macOS 的交互式安装器。它从 GitHub Release 下载当前 Mac 架构的预编译二进制，校验 `SHA256SUMS` 后安装到 `/usr/local/bin/remotemac`，再创建用户级 LaunchAgent。

安装器**不会从本地源码构建**，运行安装器不需要 Go、Node.js、pnpm 或 Make，也不要求用户先克隆 RemoteMAC 仓库。

> [!WARNING]
> RemoteMAC 当前仍是实验性项目。安装脚本、虚拟显示器和不同 macOS 版本的组合需要在目标 Mac 上单独验收。安装服务前请先阅读 README 的[权限与安全](../README.md#权限与安全)说明。

## 适用范围与前提

安装器当前仅支持 macOS，并且要求从已登录的图形桌面用户运行。它不支持 Linux、Windows、无图形会话的 SSH 环境或非交互式管道输入。

安装前需要具备：

- `curl`，用于通过 HTTPS 下载 Release；
- `unzip`，用于提取二进制；
- `shasum`，用于校验 SHA-256；
- 可用的 `sudo`，用于写入 `/usr/local/bin`；
- 可读写的交互式终端 `/dev/tty`。

安装器不会安装上述依赖。macOS 通常已自带 `curl`、`unzip` 和 `shasum`。建议以普通登录用户运行，不要直接以 root 执行；写入系统程序目录时脚本会单独调用 `sudo`。

## 安装

### 最新 Release

无需克隆源码，直接执行：

```sh
curl -fsSL https://raw.githubusercontent.com/ynhuu/RemoteMAC/main/install.sh | sh -s -- install
```

该命令会执行公开仓库中的安装脚本。若需先审阅脚本：

```sh
curl -fsSL https://raw.githubusercontent.com/ynhuu/RemoteMAC/main/install.sh \
  -o /tmp/remotemac-install.sh
sh /tmp/remotemac-install.sh install
```

默认从 `ynhuu/RemoteMAC` 的 `latest Release` 下载。也可以固定版本，或指定镜像仓库：

```sh
sh /tmp/remotemac-install.sh install --version v1.0.0
sh /tmp/remotemac-install.sh install --repo owner/repository
```

查看用法：

```sh
sh /tmp/remotemac-install.sh --help
```

### 交互配置

下载并校验资产后，安装器会交互询问：

1. **监听地址**：默认 `0.0.0.0`，可输入 IPv4 或 IPv6 地址；IPv6 不加方括号。
2. **监听端口**：默认 `28080`，范围为 `1–65535`。
3. **访问口令**：输入两次，输入时不会回显，不能为空。
4. **最终确认**：确认后才会安装程序并创建后台启动项。

监听地址决定哪些设备可以访问服务：

- `127.0.0.1`：仅本机访问；
- `0.0.0.0`：监听所有 IPv4 网卡，适合可信局域网，但暴露面更大；
- 指定局域网 IP：只监听指定网卡。

安装完成后访问：

```text
http://<Mac 的局域网 IP>:28080
```

本机健康检查不需要登录：

```sh
curl http://127.0.0.1:28080/healthz
```

安装器会检查 LaunchAgent 是否运行、`/healthz` 是否返回 `200`，以及未登录的 `/api/capabilities` 是否返回 `401`。它不会自动打开权限设置页，也不会验证屏幕录制或设备控制（辅助功能）权限是否已经允许。安装后请从控制端连接一次，并按 macOS 提示授权屏幕录制和设备控制（辅助功能）；授权后重启服务：

```sh
launchctl kickstart -k "gui/$(id -u)/com.remotemac.server"
```

## Release 资产

安装器按当前 CPU 架构下载以下资产：

| Mac 架构 | ZIP 资产 | ZIP 内二进制 |
| --- | --- | --- |
| Apple Silicon | `remotemac-darwin-arm64.zip` | `remotemac-darwin-arm64` |
| Intel | `remotemac-darwin-amd64.zip` | `remotemac-darwin-amd64` |

同一个 Release 必须同时上传 `SHA256SUMS`。每行格式为 SHA-256 摘要、两个空格和资产文件名，例如：

```text
<64 位十六进制摘要>  remotemac-darwin-arm64.zip
<64 位十六进制摘要>  remotemac-darwin-amd64.zip
```

安装器只接受 HTTPS 下载，先校验 ZIP，再从 ZIP 中提取架构对应的二进制。校验和用于检查下载完整性，不能替代独立签名验证；请仅使用可信仓库的 Release。

开发者可以在 macOS 上生成发布资产：

```sh
make deps
VERSION=v1.0.0 make release
```

资产会写入 `bin/`，二进制内的版本号也会被设置为 `v1.0.0`。Makefile 只负责构建 ZIP 和 `SHA256SUMS`，不会创建 GitHub Release 或上传文件。

## 安装过程

安装器的主要步骤如下：

1. 检查操作系统、当前用户、交互终端、架构和依赖命令；
2. 检查 GitHub Release 参数和资产名称；
3. 下载对应架构 ZIP 与 `SHA256SUMS`；
4. 校验 ZIP 的 SHA-256，并提取对应二进制；
5. 检查受管理路径，拒绝覆盖不属于 RemoteMAC 的已有文件或符号链接；
6. 交互询问监听地址、端口和访问口令；
7. 安装二进制、配置、运行脚本和 LaunchAgent plist；
8. 通过 `launchctl bootstrap` 启动服务并执行健康检查。

访问口令不会写入 LaunchAgent plist、命令参数或日志。后台运行脚本启动时从 `~/.config/remotemac/password` 读取口令，并通过 `REMOTEMAC_TOKEN` 环境变量传给服务。

如果下载、校验、输入、启动或健康检查失败，临时文件会被清理；安装配置可能保留，以便查看日志或执行卸载。安装器不会声称能够对所有步骤执行事务性回滚。

## 文件与后台服务

| 路径 | 用途 | 权限 / 说明 |
| --- | --- | --- |
| `/usr/local/bin/remotemac` | 已安装的本机架构二进制 | `755`，写入需要管理员授权 |
| `~/.config/remotemac/password` | 访问口令 | `600` |
| `~/.config/remotemac/settings` | 监听地址和程序路径 | `600` |
| `~/.local/share/remotemac/run` | LaunchAgent 使用的启动脚本 | `700` |
| `~/.local/share/remotemac/installed` | 安装标记 | 用于识别受管理安装 |
| `~/Library/LaunchAgents/com.remotemac.server.plist` | 用户级登录启动项 | `600` |
| `~/Library/Logs/RemoteMAC/server.log` | 标准输出日志 | 由 LaunchAgent 写入 |
| `~/Library/Logs/RemoteMAC/server-error.log` | 标准错误日志 | 由 LaunchAgent 写入 |

LaunchAgent 使用当前用户的图形登录会话，设置了 `RunAtLoad` 和 `KeepAlive`。它不会打开 Terminal 窗口，也不会在无人登录图形桌面时运行。

查看已安装二进制的版本：

```sh
/usr/local/bin/remotemac -version
```

## 查看状态与日志

LaunchAgent 标签为 `com.remotemac.server`。查看当前用户的服务状态：

```sh
launchctl print "gui/$(id -u)/com.remotemac.server"
```

查看服务日志：

```sh
tail -f "$HOME/Library/Logs/RemoteMAC/server.log"
tail -f "$HOME/Library/Logs/RemoteMAC/server-error.log"
```

验证服务和鉴权边界：

```sh
curl -i http://127.0.0.1:28080/healthz
curl -i http://127.0.0.1:28080/api/capabilities
```

后一个请求未携带登录 Cookie 时应返回 `401`。如果安装时指定了其他监听地址或端口，将命令中的主机和端口替换为对应配置。

## 更新

安装器没有单独的 `update` 子命令。再次执行安装命令时，脚本会下载指定版本或最新 Release；如果检测到现有 RemoteMAC 安装，会询问是否替换：

```sh
curl -fsSL https://raw.githubusercontent.com/ynhuu/RemoteMAC/main/install.sh | sh -s -- install
```

更新前建议：

1. 保存当前工作并确认访问口令仍可用；
2. 确认 GitHub Release 包含当前架构资产和 `SHA256SUMS`；
3. 更新后重新检查 `/healthz`、日志、屏幕录制和设备控制（辅助功能）权限；
4. 如果更新了 macOS 系统或虚拟显示相关实现，重新进行真实设备验收。

## 卸载

无需网络，也不需要 Release 参数。使用安装时的登录用户执行：

```sh
sh /tmp/remotemac-install.sh uninstall
```

如果临时脚本已删除，可重新下载脚本后执行 `uninstall`。确认后，脚本会：

- 停止并禁用 `com.remotemac.server`；
- 删除安装器复制到 `/usr/local/bin` 的程序、启动项、口令、监听配置、运行脚本和安装标记；
- 删除 RemoteMAC 创建的服务日志；
- 包含其他文件的目录会保留。

脚本只删除明确由 RemoteMAC 管理的文件，不会递归删除包含其他文件的目录，也不会删除系统文件。没有找到受管理安装记录时，卸载会停止并提示错误。

## 故障排查

### 下载失败或找不到 Release

确认仓库公开可访问，且 Release 已上传：

- 当前架构对应的 ZIP；
- ZIP 内与约定一致的二进制文件名；
- 包含对应 ZIP 文件名的 `SHA256SUMS`。

也可以固定已知版本重试：

```sh
sh /tmp/remotemac-install.sh install --version v1.0.0
```

### `需要交互终端才能完成安装`

安装器需要从 `/dev/tty` 读取地址、口令和确认。不要通过后台任务、CI 或不提供终端的管道调用；`curl ... | sh -s -- install` 仍要求目标机器存在可用的交互终端。

### 服务未通过健康检查

检查 LaunchAgent 和错误日志：

```sh
launchctl print "gui/$(id -u)/com.remotemac.server"
tail -n 100 "$HOME/Library/Logs/RemoteMAC/server-error.log"
```

如果服务启动后立刻退出，常见原因包括端口已占用、Release 架构不匹配、访问配置损坏或 macOS 原生环境不满足要求。失败时配置可能仍会保留。

### 能打开登录页但无法连接桌面

首次连接时，请按 macOS 提示允许 RemoteMAC 进行屏幕录制和设备控制（辅助功能）；授权后执行：

```sh
launchctl kickstart -k "gui/$(id -u)/com.remotemac.server"
```

确认 macOS 的“隐私与安全性”中已允许：

- 屏幕录制；
- 设备控制（辅助功能，用于键盘和鼠标输入）。

同时确认控制端和 Mac 处于可信且可互通的网络中。RemoteMAC 没有 TURN 中继，HTTP 信令也没有 TLS，不能直接作为公网服务使用。

## 发布者检查

检查安装脚本语法：

```sh
sh -n install.sh
```

构建并检查项目：

```sh
make check
make release
```

`make check` 不会安装或卸载 LaunchAgent。真实安装、登录启动、屏幕录制权限、设备控制（辅助功能）权限和完整卸载仍需要在目标 macOS 用户环境中单独验证。上传 Release 前应确认 ZIP 内容、文件名和 `SHA256SUMS` 与本页约定一致。
